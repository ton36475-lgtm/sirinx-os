## 1. ข้อเท็จจริงของเว็บปัจจุบัน (VERIFIED จากโค้ดจริง)

- `apps/sirinx-site` เป็น **static HTML ล้วน** — `package.json` มี `dependencies: []` ไม่มี framework
- หน้าที่มีอยู่: `src/index.html` (573 บรรทัด), `src/projects/index.html` (193), `contact/`, `quote/`, `roi-calculator/`, `line/`, `trust-center/`
- `src/projects/index.html` ปัจจุบันเป็นหน้า **"กระบวนการ/ความสามารถ"** — มี `proof-stage-card` 4 ใบ กับ `project-service-grid` **ยังไม่มีเคสลูกค้าจริงสักเคส**
- asset อยู่ที่ `src/assets/optimized/`
- deploy ผ่าน Cloudflare (`wrangler.jsonc`)

### ข้อจำกัดที่ห้ามแตะ — closed gate

`scripts/closed-gate-checks.mjs` บล็อกสิ่งเหล่านี้ใน HTML ที่ ship ออกไป:

- `HTML form submit` / `form action attribute`
- `browser network call` / `API endpoint link`
- `browser storage`
- `analytics beacon send` / `production analytics SDK` / `production analytics vendor`
- `Supabase client/runtime wiring` / `MongoDB connection string`

**ผลต่อแผนนี้:** หน้าเคสสตัดดี้ต้องเป็น HTML/CSS ล้วน แกลเลอรีรูปห้ามใช้ JS ที่ยิงเน็ต ห้ามฝัง analytics ห้ามมีฟอร์มในหน้า ปุ่ม CTA ให้ลิงก์ไปหน้า `contact/` หรือ `quote/` ที่มีอยู่แล้วแทน

## 2. สิ่งที่ต้องได้จากฝั่ง SIRINX ก่อนเริ่ม (blocking)

ผมเขียนโค้ดได้ แต่**เขียนตัวเลขและรูปแทนไม่ได้** ต้องได้ของจริงมาก่อน:

| # | สิ่งที่ต้องการ | เหตุผล |
|---|---|---|
| 2.1 | **รูปถ่ายหน้างานจริง** เรือนแพรอยัลปาร์ค ขั้นต่ำ 4–6 รูป (มุมกว้างเห็นอาคาร, แผงบนหลังคา, ตู้ควบคุม/อินเวอร์เตอร์, ทีมงานขณะติดตั้ง) | หน้าเคสสตัดดี้ที่ไม่มีรูปจริง = โฆษณา ไม่ใช่ผลงาน |
| 2.2 | **ขนาดระบบจริง** (kWp), จำนวนแผง, รุ่นแผง, รุ่นอินเวอร์เตอร์, วันที่ติดตั้งเสร็จ | เป็นข้อเท็จจริงที่ตรวจสอบได้ |
| 2.3 | **ตัวเลขผลลัพธ์ + ที่มา** เช่น หน่วยที่ผลิตได้/เดือน หรือค่าไฟที่ลดลง พร้อมระบุว่ามาจากบิลจริง / มิเตอร์ / ระบบมอนิเตอร์ ช่วงเวลาไหน | ดูข้อ 5 |
| 2.4 | **หนังสือ/ข้อความยินยอม** ให้ใช้ชื่อโรงแรม โลโก้ และรูปในสื่อการตลาด | แม้เป็นโรงแรมของผู้บริหารเอง ก็ยังเป็นคนละนิติบุคคลกับ SIRINX |
| 2.5 | คำรับรองจากเจ้าของ/ผู้จัดการ (ถ้าต้องการใส่) พร้อมชื่อ-ตำแหน่งที่อนุญาตให้เผยแพร่ | optional |

**ถ้ายังไม่มีข้อ 2.3** ยังเดินหน้าได้ โดยทำหน้าแบบ "ผลงานติดตั้ง" (system spec + รูป) ไปก่อน แล้วเติมส่วนผลลัพธ์ทีหลัง — ดีกว่าใส่ตัวเลขประมาณการ

## 3. งานที่จะทำ — Phase 1

### 3.1 โครงสร้างไฟล์

```
apps/sirinx-site/src/
├─ projects/
│  ├─ index.html                    ← แก้: เพิ่มการ์ดผลงานจริงด้านบน proof-stage เดิม
│  └─ ruenphae-royal-park/
│     └─ index.html                 ← ใหม่: หน้าเคสเต็ม
└─ assets/optimized/projects/ruenphae-royal-park/
   ├─ hero.webp
   ├─ rooftop-01.webp … rooftop-0N.webp
   └─ inverter-01.webp
```

**ทำไมแยกหน้าลูก** — `projects/index.html` ปัจจุบัน 193 บรรทัด ถ้ายัดเคสเต็มลงไปจะบวมและ Phase 2 จะยิ่งหนัก แยกหน้าลูกตั้งแต่ต้นทำให้ Phase 2 แค่เพิ่มโฟลเดอร์ ไม่ต้องรื้อ

### 3.2 โครงหน้าเคส (ตามลำดับ)

1. **Hero** — ชื่อโรงแรม, จังหวัด, ขนาดระบบ (kWp), เดือน/ปีที่ติดตั้งเสร็จ, รูปหน้างานเต็มความกว้าง
2. **ที่มา/โจทย์** — โรงแรมเจอปัญหาอะไร (ค่าไฟพีคช่วงไหน, ข้อจำกัดหลังคา, ข้อจำกัดช่วงมีแขกพัก)
3. **สิ่งที่ติดตั้งจริง** — ตารางสเปก: แผง (รุ่น/จำนวน/กำลัง), อินเวอร์เตอร์, โครงสร้างรองรับ, ระยะเวลาหน้างาน
4. **แกลเลอรีหน้างาน** — grid รูปจริง มี `alt` ภาษาไทยทุกรูป
5. **ผลลัพธ์** — เฉพาะตัวเลขที่มีที่มา แต่ละตัวต้องมีบรรทัดกำกับว่าวัดจากอะไร ช่วงไหน
6. **CTA** — ลิงก์ไป `/quote/` และ `/contact/` (ลิงก์ธรรมดา ไม่ใช่ฟอร์ม)

### 3.3 การ์ดบนหน้า `projects/index.html`

เพิ่ม section ใหม่ **เหนือ** `proof-stage-grid` เดิม ชื่อประมาณ "ผลงานติดตั้งจริง" มีการ์ด 1 ใบชี้ไปหน้าเคส — โครง grid รองรับหลายใบตั้งแต่แรกเพื่อ Phase 2

**ไม่แตะ** `proof-stage-grid` และ `project-service-grid` เดิม — ของเดิมผ่าน gate อยู่แล้ว ไม่มีเหตุให้รื้อ

## 4. Gate ที่ต้องผ่านก่อนขึ้นจริง

รันตามลำดับนี้ ทุกตัวต้องเขียว:

```bash
pnpm --filter @sirinx/site check
pnpm --filter @sirinx/site build
pnpm --filter @sirinx/site test:closed-gates
pnpm --filter @sirinx/site test:server
pnpm --filter @sirinx/site review:local
pnpm --filter @sirinx/site review:screenshots
pnpm --filter @sirinx/site auto-review:website
pnpm --filter @sirinx/site release:readiness
pnpm --filter @sirinx/site manual:review-gate
```

`manual:review-gate` เป็นด่านคน — ต้องมีคนดูจริงก่อนปล่อย

**การ deploy ไม่อยู่ในแผนนี้** — `CLAUDE.md` ระบุว่าห้าม deploy โดยไม่มีการอนุมัติจากคนอย่างชัดเจน แผนนี้จบที่ "commit ready + gate เขียวครบ"

## 5. เรื่องตัวเลข — ข้อควรระวังที่สำคัญที่สุด

หน้าเคสสตัดดี้ของงานพลังงานคือ**การกล่าวอ้างต่อสาธารณะ** ตัวเลขที่ผิดหรือไม่มีที่มาสร้างความเสี่ยงจริงต่อบริษัท

กติกาที่ผมจะใช้เขียน:

- ทุกตัวเลขต้องมีที่มาที่ระบุได้ — บิลค่าไฟ, มิเตอร์, หรือระบบมอนิเตอร์ พร้อมช่วงเวลา
- ถ้าเป็นค่าประมาณการ **ต้องเขียนกำกับว่าประมาณการ** และบอกสมมติฐาน
- ห้ามใช้คำรับประกันผลตอบแทน ("คืนทุนแน่นอนใน X ปี") — เขียนเป็นช่วงพร้อมเงื่อนไขแทน
- ถ้าข้อมูลยังไม่ครบ **เว้นส่วนนั้นไว้** ดีกว่าเติมตัวเลขให้ดูสวย

ถ้าผู้บริหารอยากได้ตัวเลขที่ยังไม่มีหลักฐาน ผมจะทำหน้าให้โดยเว้นช่องนั้นไว้ แล้วแจ้งว่าเว้นเพราะอะไร

## 6. Phase 2 — โฮลาเทลริมน่าน

โครงจาก Phase 1 รองรับอยู่แล้ว งานที่เหลือคือ:

1. เพิ่ม `src/projects/hola-hotel-rim-nan/index.html` ตามโครงเดิม
2. เพิ่มการ์ดใบที่สองใน grid
3. ต้องการของจาก §2 ชุดเดียวกันสำหรับโรงแรมนี้
4. รัน gate ชุดเดิม

**สิ่งที่ควรตัดสินใจตอน Phase 2 ไม่ใช่ตอนนี้:** ถ้าเคสจะเกิน ~4 หน้า ค่อยพิจารณาย้ายเนื้อหาไปเป็น data file + generator ตอนนี้ยังไม่คุ้มที่จะทำ
