4. Strengths

  • Clear 5-phase recovery ordering (thermal to disk to git to cron to service) is a safe sequence.
  • AgentLensManager uses threading.Lock + resource locks + status-lock anti-deletion for good isolation.
  • BrainStorm 6-factor + 4-tier approval with human escalation on critical/security/financial is sound governance.
  • A2A JSON-Schema is well-structured and versioned (kimi3/kimiswarm3 versions).
  • Dashboard + production.md give the team a single source of truth.
  • QA veto gate (Hermes-QA) before any deploy is the correct human-in-code pattern.

5. Critical Defects

IDSevFileIssue / Impact / Fix
D1CRITICALomniroute_swarm_orchestrator.py / sirinx_crisis_recovery.pyIssue: Auto-deploy runs git add -A and git commit; Wayu emits APPROVE_AND_TRIGGER_GIT_PUSH then Hermes-QA APPROVED triggers _deploy() which commits. No human approval, no dry-run, no branch protection. Violates AGENTS.md A5/A6 and the project no-push-without-approval rule.
Impact: Unattended code could be committed/pushed to migration/v5-rebase automatically.
Fix: Gate _deploy behind explicit human confirmation; default to dry-run; never auto-commit on main tree.
D2CRITICALsirinx_crisis_recovery.py (git_protection)Issue: On submodule failure it runs git rm -f integrations/cynative then git commit -m non-interactively. Mutates working tree and commits without review.
Impact: Silent destructive mutation of repo history.
Fix: Never auto-commit; only stash; report submodule error for human.
D3HIGHsirinx_crisis_recovery.py (disk_recovery)Issue: Uses bare shutil.rmtree(target/) and os.remove walks in ~/.hermes / ~/.codex with try/except but no allowlist/dry-run guard. Could delete recent sessions/cache. Same destructive pattern your background codex audit was meant to harden.
Impact: Potential loss of recent Codex/Hermes sessions if paths drift.
Fix: Add allowlist (only __pycache__, ~/.npm/_cacache, /tmp) + SELF_EVOLUTION_ALLOW_PURGE opt-in dry-run.
D4HIGHsirinx_crisis_recovery.py / telegram controllerIssue: get_live_metrics hardcodes fallback disk 228/191/11/95 and PIDs 2620/2630/2705; disk_recovery frees estimated space (space_freed += 3.3 for npm without verifying). Metrics are synthetic, not measured.
Impact: Recovery report can claim success while disk stays 95%.
Fix: Compute real freed bytes from before/after du; remove hardcoded guesses.
D5MEDIUMomniroute_swarm_orchestrator.pyIssue: Calls Ollama models (deepseek-coder-v2:16b, llama3:70b-q4, qwen2.5:32b, glm-edge-code:uncensored, baidu/Unlimited-OCR) not verified present on this 8GB M2. 70B model cannot load on 8GB. No model-availability check. Declares 47 Ronin but only 7 agents defined.
Impact: Swarm loop fails at first agent call; roster mismatch.
Fix: Pre-flight model check; right-size models to M2 (8B/14B max); reconcile 47 vs 7.
D6MEDIUMgithub_actions_auto_recovery.ymlIssue: deploy job runs wrangler deploy + supabase db push + git push --tags automatically on success — cloud mutation + push without human gate. Runs on macos-latest, not the M2.
Impact: Unattended production deploy from CI.
Fix: Add environment protection / required reviewer; gate auto-push behind manual approval.
D7LOWagent_communication_schema.json / promptsIssue: Schema references 9 AgentRoles incl strategic_advisor but orchestrator defines 7; brainstorm consensus hardcodes only 4 agents. Inconsistent agent registry.
Impact: Schema/code drift in agent roster.
Fix: Single source-of-truth agent registry shared by schema + orchestrator + brainstorm.
D8LOWsirinx_crisis_recovery.py (syntax)Issue: handoff() uses state['handoff_at': None] = ... — invalid dict literal. Would SyntaxError if handoff invoked. (The main-file copy uses __main__ correctly; this is in the recovered snippet.)
Impact: Runtime crash if handoff invoked.
Fix: Fix to state['handoff_at'] = datetime.utcnow().isoformat().

6. Security Posture

Good:
  • Command blocklist in kudu_sysops prompt (no rm -rf /, no chmod 777, no sudo)
  • BrainStorm human escalation on critical/security
  • Never git reset --hard (uses stash) — aligns with your root-cause bug
Gaps:
  • No actual allowlist enforcement in Python (only documented in prompts)
  • Secrets (TELEGRAM_BOT_TOKEN, CLOUDFLARE_API_TOKEN, POSTGRES_PASSWORD=sirinx2026) in plaintext in docker-compose/env appendices
  • auto-deploy bypasses the documented human gate

7. Recommendation

ARCHITECTURE APPROVED FOR REVIEW. Do NOT run on this Mac mini in current form: D1/D2 (auto-commit/deploy) and D3 (unguarded rmtree) violate project safety law. Recommend: (1) add dry-run+allowlist to recovery, (2) gate _deploy behind human approval, (3) verify models fit 8GB M2, (4) reconcile agent registry. Then pilot in staging.
