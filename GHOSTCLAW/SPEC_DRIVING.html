2. Agent Roster

🎯 Hermes
Mission Commander · A5
Routes missions, creates lanes, reads Brain, prevents loops & collisions.
No direct repo writes. Approval required for push/deploy.
🏗️ Opus
Chief Architect · A3
Designs architecture, data models, protocols. Outputs design docs only.
No repo writes, no commits, no deploy.
⚓ Codex
Build Captain · A4
Scaffolds, integrates patches, runs tests, stages commits.
No push/merge without approval.
👷 GLM-5.2
Coding Worker · A3
Writes modules, tests, bug fixes within assigned lane.
No architecture decisions, no cross-lane writes.
🧠 DeepSeek
Reasoning Worker · A3
Deep debugging, refactoring, algorithm work within assigned lane.
No UI work, no architecture, no integration.
🔍 KOB
Validator · A2
Runs tests, lint, typecheck. Allowlisted commands only.
No file writes, no git ops, no arbitrary shell.

5. A2A2A Protocol

Agent → Agent → Action

A₁ Agent Request

Hermes issues structured mission order with goal, lane, constraints, TTL.

A₂ Agent Process

Opus/Codex/Workers analyze, design, write, integrate within lanes.

A₃ Action

KOB validates. Command Broker gates execution. Mission Control records.

7. Mission Lifecycle

1. OPERATOR → Hermes: "Build feature X"
2. Hermes → Opus: Design architecture
3. Opus → Hermes: architecture.md
4. Hermes → Codex: Build X per architecture
5. Codex → GLM / DeepSeek: Write modules
6. Workers → Codex: Patches
7. Codex integrates + local tests
8. Codex → KOB: Validate
9. KOB → Codex: validation-report.json
10. Codex → Command Broker: Request commit
11. Broker gates → allows/blocks
12. Hermes → 📜 Scribe: Record mission
13. Hermes → OPERATOR: ✅ MISSION COMPLETE

8. Safety Rules

✗ No deploy without human approval
✗ No git push without human approval
✗ No cloud mutation without human approval
✗ No .env reads
✗ No secrets in context
✗ No cross-lane writes without routing
✗ No worker-to-worker direct comms
⚠ Dry-run first for external actions
⚠ Loop guard: max 2 retries, circuit breaker at 3
